Database indexes make lookups fast by imposing order on records. A relational table can grow huge, so scanning every row for one record is wasteful. A B-tree index keeps keys sorted and balanced, turning an expensive full scan into a short path to the target record. The query planner chooses which index to use based on selectivity and cost. Range scans benefit too, because adjacent keys sit close together in the tree. Lookups that miss the index fall back to a sequential scan, which is the slowest option. Choosing the right index columns is therefore a core tuning decision for any database workload.
