ZMWiki turns plain documents into linked wiki pages, then lets an agent search, read, and follow those links on your machine. The core is a Python library — deterministic by default, model-agnostic when you connect a live endpoint.

The core

A retrieval loop you can inspect.

No opaque pipeline. Each stage is a small, testable module with a defined contract, and every answer points back to pages the agent actually read.

  • Linked pages

    Stable ids, paths, aliases, tags and bidirectional links — not anonymous text chunks.

  • Two-signal search

    Metadata BM25 and content BM25 fused deterministically. Results carry metadata, not page bodies.

  • Evidence-aware agent

    Search candidates never count as evidence. Only pages opened through wiki_read do.

  • Measured, not asserted

    Offline retrieval metrics and a multi-hop benchmark with per-step diagnostics.

Features

Six modules. One local loop.

These are shipped modules in the repository today. The browser workbench is not one of them — it is on the roadmap.

01wiki_schema.py

Structured Wiki Pages

Every page carries a stable id, path, title, aliases, tags, source ids and bidirectional links. Pages serialize to JSON-ready dicts and validate on construction.

02wiki_retriever.py

Metadata-First Search

wiki_search ranks title, alias, tag and description matches first, fuses content BM25, then returns candidate metadata — never full page bodies.

03wiki_retriever.py

Evidence-Aware Reading

wiki_read fetches pages by path in input order and fails loudly on missing paths. Only pages actually read enter the agent’s evidence set.

04wiki_agent.py

Budgeted Multi-Step Agent

Search, read, follow links, answer. Step limits, duplicate-action suppression and consecutive protocol-error caps are enforced in code, not by prompt alone.

05wiki_compiler.py

Source-Aware Compilation

WikiCompiler turns one document into one structured page through an OpenAI-compatible endpoint and keeps the source document id on the page.

06benchmark/

Measurable Retrieval

Offline retrieval metrics, deterministic answer scoring and an internal 26-case multi-hop benchmark track evidence recall and per-step failures without an LLM judge. These are repository-local diagnostics, not a general accuracy claim.

Workflow

From raw text to a traceable answer.

  1. 01

    Ingest

    Plain text documents or a directory, loaded through the existing ingestion contracts.

  2. 02

    Compile & Index

    Pages are compiled with sources retained. The index builds metadata and content BM25.

  3. 03

    Search

    Metadata-first ranking returns candidate pages with scores and no page bodies.

  4. 04

    Read

    Full pages are fetched by path. Their links become the next set of traversal options.

  5. 05

    Answer

    The agent answers from pages it actually read, with sources kept separate from model text.

Agent loop
search→ read→ follow_links→ answer

Bounded by max_steps, duplicate suppression and a consecutive protocol-error limit.

Install

The library, not a platform.

Clone the repository and install it in editable mode. The default install is dependency-free and runs without a model or network.

  • Python 3.10 or newer
  • No runtime dependencies
  • Wiki and benchmark tests run offline

A read-only local HTTP server ships with the package (python -m zmwiki.web.server). The browser workbench is still on the roadmap.

~/zmwiki 
$ git clone https://github.com/lip20041219/zmwiki.git
$ cd zmwiki
$ pip install -e .
$ python -m pytest tests/wiki -q

FAQ

Questions worth asking.

Short answers, no cloud marketing.

Is my knowledge sent to a cloud?

No by default. Indexing, search, reading and the deterministic evaluation paths run locally. Only model calls you configure — compilation, agent reasoning or generation — leave the machine, and they go to the endpoint you choose.

Do I need an API key?

Not for the deterministic RAG pipeline or the offline benchmarks. Compilation and the live agent need an OpenAI-compatible endpoint; the key is read from your environment or passed in code. It is never part of the static site.

Is there a browser workbench or local server?

The package ships a read-only local HTTP server: python -m zmwiki.web.server --workspace path/to/wiki.json. It serves page list, page detail and search APIs over the same workspace. A browser workbench (search, read, ask) is still in progress.

Where is my wiki stored?

Wiki pages live in a JSON workspace file that the TUI loads at startup and saves with S (press twice to overwrite an existing file); local document imports save automatically. Without --workspace, the bundled demo workspace is opened read-only. Benchmark artifacts are separate JSON files under benchmark/results/.

What document formats are supported?

Plain text and directories of .txt files, through the existing ingestion modules. PDF and Markdown parsing are not implemented.
